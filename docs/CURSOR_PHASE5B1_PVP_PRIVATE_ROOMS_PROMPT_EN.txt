6. WEBSOCKET CONTRACT AND SECURITY
===============================================================

Keep existing connection.ready and connection.error unchanged.
Extend protocol v1 with versioned, validated messages such as:

Client -> Node:
- room.subscribe { grant }
- room.unsubscribe { room_id }

Node -> Client:
- room.subscribed { room_id, version }
- pvp.room.changed { room_id, version }
- pvp.invitation.changed { invitation_id }
- room.subscription.revoked { room_id, reason }

Do not send client combat commands or full private opponent data through the socket.
No public room join by room ID alone.
Do not store credentials in localStorage or WS URLs.
Do not log grants, one-use tickets, private URLs or bearer tokens.
Use TLS/WSS outside local development.

Address logout/revocation behavior explicitly. A long-lived authenticated socket must not remain authorized indefinitely after its user is revoked or removed from a room. Implement and test a safe enforcement approach rather than merely documenting it as secure.
